# Growing Villages

Аддон для Minecraft Bedrock Edition: ванильные деревни заменяются на
растущие — игрок находит крошечное поселение и вкладывает ресурсы в
ратушу, чтобы поднимать её по уровням.

Деревня растёт по перекрёстку из двух улиц с четырьмя воротами, стена
расширяется вместе с ней, а свободная земля внутри застраивается районами:
жилыми дворами, мастерскими, колодцем, мельницей, караулкой. Приходят
ремесленники с квестовыми цепочками, дозорные ходят по стене, жители по
вечерам собираются у колокола на площади. У старосты есть ежедневные подряды,
а «Разведочная грамота» размечает вокруг деревни находки — заброшенную шахту,
руины башни, лесной лагерь, старый карьер.

Ключевой принцип — гармония с ванилью: только ванильные блоки и текстуры,
ничего оверпаверного, экономика игрока не ломается.

**Совместимость.** Планировка-перекрёсток применяется к деревням, основанным
начиная с 0.6.0. Деревни из старых сохранений остаются на прежней планировке
и продолжают работать.

Текущая версия — см. `header.version` в `GrowingVillages_BP/manifest.json`
(любое число, зафиксированное тут, устареет). Целевой движок — Bedrock
**1.26.40+**, скриптовый модуль `@minecraft/server 2.9.0`.

Требование не произвольное: мод использует `Potions` (зелья алхимика) и
`Dimension.getBiome` (палитра построек по биому), а они появились в
`@minecraft/server` 2.4.0 и 2.3.0 соответственно; сама стабильная 2.0.0
вышла только с Minecraft 1.21.90. Пак, объявляющий движок ниже нужного,
не падает с ошибкой — он молча теряет эти возможности, поэтому пара
«движок ↔ версия модуля» проверяется тестом `tests/pack_integrity.mjs`,
а не на глаз.

## Структура

- `GrowingVillages_BP/` — behavior pack (скрипты в `scripts/`, предметы в `items/`)
- `GrowingVillages_RP/` — resource pack (текстуры, тексты)
- `tests/` — эмулятор Bedrock Script API на Node.js и наборы тестов
- `tools/build.mjs` — сборка `.mcaddon` (`node tools/build.mjs`, выход в `dist/`)
- `HANDOVER.md` — полная передача контекста проекта (архитектура, грабли,
  баланс, сборка, установка на устройство)
- `ROADMAP_20_FEATURES.md` — двадцать фишек, разбитые по релизам, и что уже сделано
- `RELEASE_NOTES_0.12.0.md` — текущий релиз; рядом заметки к 0.11.0 и 0.10.0

## Разработка

Полный контекст для продолжения разработки — в [`HANDOVER.md`](HANDOVER.md).
Начни с него.

### Тесты

`tests/` — эмулятор Bedrock Script API на Node.js. `tests/run-all.mjs` сам
синхронизирует `tests/scripts` из `GrowingVillages_BP/scripts` (эта копия —
рабочая, в git не хранится, см. `.gitignore`) и прогоняет все наборы:

```bash
node tests/run-all.mjs              # весь набор
node tests/run-all.mjs lint spatial # только наборы с этими словами в имени
```

Отдельный тест можно запустить и напрямую, но тогда синхронизируй код сам —
иначе тест проверит старую копию:

```bash
rm -rf tests/scripts && cp -r GrowingVillages_BP/scripts tests/scripts
node tests/имя_файла.mjs
```

На каждую задачу пиши новый узкий тест под конкретную правку, а не
перезапускай весь исторический `tests/*.mjs` по умолчанию — подробности
и когда всё же стоит прогнать всё целиком — в [`HANDOVER.md`](HANDOVER.md).

### Правило про текст

Мод пока одноязычный, и переводить те ~400 русских строк, которые уже лежат
в скриптах, в план не входит. Но **новый** игровой текст пишется через ключи
`growing_villages.*` и `GrowingVillages_RP/texts/ru_RU.lang`, даже пока
заполнен только русский, — так это уже сделано для цепочек ремесленников,
арки дозорного и экранов L16–20.

Это сторожит `tests/lang_ratchet.mjs`: число захардкоженных строк в файле не
может вырасти относительно `tests/lang_baseline.json`, а у нового модуля
должно быть нулевым. Если строки наоборот убрали — перезапиши базу, чтобы
храповик затянулся:

```bash
node tests/lang_ratchet.mjs --write
```

Смысл не в том, чтобы что-то перевести сейчас, а в том, чтобы цена будущего
перевода перестала расти с каждым релизом.
